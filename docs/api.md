# API

フロントエンドとバックエンドの間の取り決めです。実装の正は `back/src/` で、起動中は http://localhost:8000/docs でも確認できます。

- パスはすべて `/api/` から始まる。フロントからは相対パスで呼ぶ。
- 送る内容と返る内容は JSON。項目名は `snake_case`。ただし、線のデータの項目（`pointerType` など）は、分析側の資料の名前に合わせている。

## 一覧

API の一覧は [api-list.md](api-list.md) にまとめています（実装済みのもの、分析側のブランチにあるもの、Worker に頼む口、まだないもの）。この文書は、実装済みの API のくわしい形を書きます。

## GET /api/health

返る内容（200）:

```json
{ "status": "ok", "service": "backend", "version": "0.1.1" }
```

## POST /api/drawings

キャンバスで「確定」を押したときに呼ばれます。受け取った画像を白黒 1 チャネルにして 1024 × 1024 と 256 × 256 に縮小し、線のデータと一緒に保存して、台帳に 1 行書きます。応答で、結果（くつしたとメッセージ）を返します。

結果は、分析ができるまでの仮のものです（下の「仮の結果」）。

線のデータ（`target`・`canvas`・`strokes`）の形は、分析側の資料（「フロントから毎回届くもの」）に合わせています。違うところは下の「分析側の資料との対応」にあります。

送る内容:

| 項目 | 型 | 内容 |
|---|---|---|
| `user_name` | 文字列 | 書いた人のユーザーネーム。省略できる。省略したとき、空のとき、空白だけのときは `User` として記録する。前後の空白を取ってから数えて 15 文字まで（超えると 422）。同じ名前が何度送られてもよい。フロントは、最初の画面で入れた名前を送る（空なら `User`） |
| `target` | 文字列 | 書いた字。いまは `"と"` だけ。バックエンドが、受け取れる字の一覧（`back/src/drawings.py` の `TARGETS`）にあることを確かめる |
| `canvas` | オブジェクト | 線の座標の基準にした枠の大きさ。常に `{ "width": 1024, "height": 1024 }`。端末の画面の大きさに関係なく、枠を 1024 × 1024 とみなした座標で送る（保存する大きいほうの画像と同じ基準） |
| `strokes` | 配列 | 線の配列。1 本以上。ポインタを押してから離すまでが 1 本。消した線は入らない。本数の上限はなく、すべての線の点を合わせて 20 万個まで |
| `strokes[].pointerType` | 文字列 | その線を書きはじめたときの入力の種類。`"mouse"`・`"touch"`・`"pen"` のどれか |
| `strokes[].points` | 配列 | 点の配列。1 個以上。点は `[x, y, t, pressure]` の 4 つの数の並び（下の「点」） |
| `image` | 文字列 | 白地に黒で描いた PNG の data URL（`data:image/png;base64,...`）。正方形で、一辺は 1024〜4096 ピクセル（下の「送る画像の大きさ」）。1600 万文字まで |
| `width` | 整数 | 送った画像の幅（ピクセル）の申告。1024〜4096。実際の画像と同じ値 |
| `height` | 整数 | 送った画像の高さ（ピクセル）の申告。`width` と同じ値 |

```json
{
  "user_name": "User",
  "target": "と",
  "canvas": { "width": 1024, "height": 1024 },
  "strokes": [
    { "pointerType": "mouse", "points": [[409.6, 184.3, 0, 0.5], [414.1, 201.9, 21, 0.5]] },
    { "pointerType": "mouse", "points": [[716.8, 337.9, 361, 0.5]] }
  ],
  "image": "data:image/png;base64,iVBORw0KGgo...",
  "width": 1112,
  "height": 1112
}
```

返る内容（201）:

```json
{
  "id": "c2e104adb43642e7b3d5477789cab7fd",
  "created_at": "2026-11-28T03:23:47+00:00",
  "sock": {
    "id": "WORN-01",
    "name": "穴あき灰色",
    "image": "/socks/worn-01.webp",
    "rarity": "使い古し",
    "comment": "灰色のウール靴下はかかとに大きな穴が開き、縁から糸が垂れている。"
  },
  "message": "あなたの「と」に、くつした「穴あき灰色」が届きました。"
}
```

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | 文字列 | 記録の ID（英数字 32 文字） |
| `created_at` | 文字列 | 記録した日時（UTC、ISO 8601） |
| `sock` | オブジェクト | 【仮】結果のくつした。`id`（くつしたの ID）、`name`（名前）、`image`（表示用の画像のパス。フロントはそのまま `<img src>` に使う）、`rarity`（レアリティの名前）、`comment`（説明）。くつしたの台帳（[socks.md](socks.md)）の同じ名前の項目の値 |
| `message` | 文字列 | 【仮】結果のメッセージ。一行 |

失敗:

| 状態 | 場合 |
|---|---|
| 413 | 本文が大きすぎる（下の「受け取る量の上限」） |
| 422 | 項目が足りない、`user_name` が 15 文字を超えている、`target` が受け取れる字でない、`canvas` が 1024 × 1024 でない、`pointerType` が 3 種のどれでもない、点のない線がある、点が 4 つの数の並びでない（以前の形 `{"x":…,"y":…,"t":…}` もここに入る）、範囲の外、`t` が整数でない、点の合計が上限を超えている、数が NaN や無限大、`image` が PNG の data URL でない、PNG として読めない、`width`・`height` が画像と合わない、正方形でない。理由は `detail` に入る（送られた値そのものは返さない。理由がたくさんあるときは、先頭の 20 件だけを返す） |
| 500 | 保存先に書き込めなかった。途中まで書いたものは消す（画像だけ、線のデータだけを残さない）。または、仮の結果を作れなかった（くつしたの台帳が読めない。このときは何も保存しない） |

### 仮の結果

`sock` と `message` は、分析（深層学習）ができるまでの仮のものです。

- くつしたは、書かれた「と」を見ずに、50 種から無作為に 1 つ選ぶ。同じ字を送っても、毎回変わる。
- メッセージは、決まった文「あなたの「と」に、くつした「（くつしたの名前）」が届きました。」に、選んだくつしたの名前を入れたもの。
- 選んだくつしたの ID とメッセージは、台帳の `sock_id` と `message` にも入れる（[data.md](data.md)）。
- 結果は、保存する前に作る。くつしたの台帳（`back/src/resources/socks.json`）が読めない、または空のときは、何も保存せずに 500 を返す（くつしたのない記録を残さない）。
- 作っているのは `back/src/drawings.py` の `make_result` だけ。分析ができたら、この関数の中身を差し替える。くつしたの台帳は `back/src/socks.py` が、最初に使うときに 1 度だけ読む。
- 分析結果のうち、読み解きと似ているフォントは、まだ返していない。

### 点

`[x, y, t, pressure]` の並びです。4 つとも数で送ります（`"412.3"` のような文字や `true` は受け取りません）。

| 並び | 内容 | 受け取る範囲 | フロントが送る値 |
|---|---|---|---|
| `x`, `y` | 枠の左上を (0, 0)、一辺を 1024 とした位置 | -1024〜2048 | 小数 1 桁に丸める。枠の外にはみ出した線は 0 未満や 1024 超になり、枠の一辺ぶん外側（-1024 と 2048）で止める |
| `t` | 最初の線を書きはじめた瞬間を 0 とした経過ミリ秒（その線の開始からではない） | 0 以上、9007199254740991（2 の 53 乗 − 1）以下の整数 | 整数に丸める。線の最後の点は、離した時刻 |
| `pressure` | 筆圧 | 0〜1 | 小数 2 桁に丸める。入力の種類ごとの値は下のとおり |

筆圧の値:

- マウス: 常に 0.5。ブラウザは、マウスのボタンを離した瞬間の筆圧を 0 と報告するが、その値は使わない。
- ペン: 端末が報告する値。
- 指: 端末が報告する値（多くの端末では 0.5）。
- 離した時刻の点には、どの入力でも、その線の直前の点の筆圧を入れる（離した瞬間は 0 と報告されるため）。
- 入力の種類がペンでも指でもない（わからない）ときは、マウスとして扱う。

筆圧と入力の種類は、データとして記録するだけです。画面の線と、送る画像の線の太さは一定で、筆圧では変わりません。

書くのにかかった時間（`duration_ms`）は送りません。バックエンドが、最後の線の最後の点の `t` を台帳に入れます。`t` が前の点より小さくなっていないかは確かめていません。

### 分析側の資料との対応

| 資料の項目 | ITO での扱い |
|---|---|
| `target` | 資料どおり。値はいまは `"と"` だけ |
| `intent` | 送っていない。ITO に意図を入れるかどうかが決まっていないため。送られてきても無視し、保存しない |
| `canvas` | 項目は資料どおり。値は、端末の枠の大きさではなく、常に 1024 × 1024（資料の例は 512 × 512）。座標も 1024 を基準にした値になる |
| `strokes[].pointerType` | 資料どおり |
| `strokes[].points`（`[x, y, t, pressure]`） | 資料どおり。`x`・`y` は上の `canvas` を基準にしたピクセル、`t` は書きはじめからの経過ミリ秒、`pressure` は 0〜1（マウスは 0.5） |
| （資料にない）`image`・`width`・`height` | ITO では送っている。画像を誰が描くか（フロントか、サーバーが線から描くか）が決まっていないので、当面はフロントが描いて送る |

資料にある「フロントへの依頼」は、次のとおり満たしています。`pointermove` では `getCoalescedEvents()` で、画面の更新より細かく届いた点も使う。線の区切りは `pointerdown` から `pointerup`（または `pointercancel`）まで。消した線は送らない。

保存する線のデータは `target`・`canvas`・`strokes` の 3 項目だけで、分析側は資料の形のまま読めます（下の「保存先」）。

### 送る画像の大きさ

- 画像は正方形。一辺は 1024 ピクセル以上、4096 ピクセル以下。
- フロントは、画面の枠を写すのではなく、覚えている線から描き起こす。一辺は「枠の画素数（表示上の大きさ × `devicePixelRatio`）」と「1024」の大きいほう（4096 を超えるときは 4096）。たとえば画素密度 2 で枠が 556 ピクセルなら 1112、画素密度 1 なら 1024。
- 1024 より小さい画像は受け取らない。バックエンドが 1024 × 1024 に引き伸ばすと、線がぼやけるため。
- 上限の 4096 は、画像を展開するときのメモリで決めている（一辺 4096 で、1 回の確定につき約 80MB）。展開する前に、PNG の先頭に書かれた大きさで確かめる。
- `width` と `height` は、実際の画像の大きさと同じでなければ 422。
- 色のついた画像や透明な部分のある画像も受け取る。透明な部分は白地に重ねてから、白黒 1 チャネルにする。16 ビットのグレースケールの PNG は受け取らない（422）。
- 下限と上限は、フロント（`front/src/components/WritingCanvas.tsx` の `MIN_IMAGE_SIZE`・`MAX_IMAGE_SIZE`）とバックエンド（`back/src/drawings.py` の同じ名前の値）で同じ値にする。片方だけ変えない。

以前あった `device_pixel_ratio`（書いた端末の画素密度）は外しました。保存する画像の大きさをそろえるようにしたので、元の画素数や画素密度は記録しません。送られてきても無視します。`duration_ms` も同じく、送られてきても無視します。

### 受け取る量の上限

線の本数には上限を置いていません（短い線をたくさん書いて塗りつぶす使い方があるため）。受け取る量は、次の 3 つで止めます。

| 上限 | 値 | 超えたとき |
|---|---|---|
| 点の合計（すべての線の点を合わせた数） | 20 万個 | 422 |
| `image` の長さ | 1600 万文字 | 422 |
| 本文全体の大きさ | 32,001,024 バイト（`image` の上限 + 点 1 個あたり 80 バイト + 1024） | 413。読み込みの途中で打ち切る |

- 点の合計の上限は、フロント（`front/src/components/WritingCanvas.tsx` の `MAX_POINTS`）とバックエンド（`back/src/drawings.py` の `MAX_POINTS`）で同じ値にする。フロントは上限に達すると、それ以上書けないようにする。片方だけ変えない。
- フロントが丸めて送る点は、JSON にすると 1 個あたり 25 バイト前後（長くても 35 バイト）。線 1 本ごとに、入れ物（`pointerType` と `points` の名前）の 36 バイトが加わる。上限いっぱいの 20 万個で、本文は 5〜14 MB になる（1 本の長い線で約 5 MB、点が 1 個だけの線ばかりで約 14 MB。画像は別に数十〜数百 KB）。どの書き方でも、点 1 個あたり 80 バイトより小さい。
- `x`・`y`・`pressure` の丸めはフロントが軽くするために行っているもので、バックエンドは丸めていない値も受け取る。`t` は整数だけを受け取る。

### 保存先

1 回の確定につき、次の 3 つを置き、台帳（表 `drawings`）に 1 行書きます。くわしい形は [data.md](data.md) にあります。

| キー | 中身 |
|---|---|
| `drawings/<id>_1024.png` | 1024 × 1024 の画像（保存用・あとで表示する用） |
| `drawings/<id>_256.png` | 256 × 256 の画像（深層学習用・一覧の小さい表示用） |
| `drawings/<id>.json.gz` | 線のデータ。`{"target": …, "canvas": {…}, "strokes": […]}` の JSON を gzip で圧縮したもの |

- 画像は、白黒 1 チャネル（8 ビットのグレースケール）の PNG。白地に黒い線で、線の縁の中間の濃さは残す（2 値化しない）。
- 置き場所は、本番ではオブジェクト置き場（Cloudflare R2）とデータベース（Cloudflare D1）の予定。いまは手元の代わりとして、コンテナ内の `/app/data/objects/`（フォルダ）と `/app/data/ito.sqlite3`（SQLite）に書く。
- 先に 3 つを置き、最後に台帳へ書く。途中で失敗したら、置いたものを消して 500 を返す。
- 台帳には、ユーザーネーム（`user_name`）と、仮の結果（`sock_id`・`message`）も入れる。
- 記録を読む API は、まだない。中身を見るコマンドは [data.md](data.md) にある。

### 決まっていないこと

- 本番の置き場（R2 と D1）へのつなぎ方。手元のデータを PC 側に残すかどうか。
- 記録を読む API（結果の画面を再読み込みしても残す場合や、一覧の画面で使う）。
- 分析結果（くつした、読み解き、メッセージ、似ているフォント）を返す API の形。いまは仮に、確定の応答に `sock` と `message` を入れて返している。分析に時間がかかるようになったとき、同じ応答で待たせるか、別の API で取りに行くか。
- お題の字（`target`）と意図（`intent`）を ITO に入れるか。いまは `target` を `"と"` の固定で送り、`intent` は送っていない。
- 画像を誰が描くか。いまはフロントが描いて `image` で送っている。サーバーが線のデータから描く方式にすると、`image`・`width`・`height` は要らなくなる。
